# 会话归档同步规则

用户希望每次 Kiro 会话的文件、聊天记录和经验都完整保存到这个仓库
（https://github.com/historycrew5423-art/kiro-chat-archive，公开仓库）。

## 会话开始时

先读 `knowledge/` 里的文档。里面是以前会话总结的工作流、踩过的坑和环境限制，
遇到同样的问题直接按文档做，不要重复试错。

## 每次会话结束前（用户不需要提醒）

1. **聊天记录**写入 `chat-history/YYYY-MM-DD[-主题].md`。同一天有多次会话时，用主题区分文件名。
   - 用户消息原文保留。
   - Kiro 的回复**保存全文**，不要只记要点。
   - 每轮加一节“Kiro 做了什么”：记录工具步骤、关键发现和结果，不贴大段原始输出。
   - 用户发的图片拿不到原文件，用文字描述画面内容。
2. **文件**放到 `files/YYYY-MM-DD-主题/`。
   - 如果文件属于用户的其他代码仓库，已经推送到那个仓库，这里只在聊天记录里写上链接，不重复复制。
3. **经验**写进 `knowledge/`：新学到的工作流、踩过的坑和修法、环境限制和绕法。
   已有主题就更新对应文档，新主题就新建文档，并在 README 的索引里加上。
4. 在 `README.md` 的内容索引里加上这次会话。
5. 提交到新分支 `sync/YYYY-MM-DD-主题` 并推送，开一个合并到 `main` 的 PR，然后由 Kiro 直接合并。
   提交信息格式：`sync: YYYY-MM-DD 主题`。把 PR 链接告诉用户。
   如果用户说想先审再合并，就改成只开 PR、不合并。

## 隐私

仓库是公开的。写入前必须去掉：密码、令牌、密钥、私有仓库名、个人身份信息、
截图里出现的他人用户名和联系人，以及工具输出里的环境变量和内部地址。拿不准的内容先问用户。
