# 归档同步：隐私处理和最后一轮回复

来自 2026-11-05 的会话。规则本身见 `.kiro/steering/archive-sync.md`，这里记具体怎么做、用户确认过什么。

## 用户确认过的隐私处理

2026-11-05 的聊天里有用户的个人经历（比赛名次、账号粉丝数）和一张与队友的微信聊天截图。Kiro 先问了用户，用户同意按下面的办法处理后上传：

| 内容 | 处理 |
| --- | --- |
| 比赛名次 | 换成“[名次已隐去]”，比赛名称保留 |
| 视频号粉丝数、小红书点赞数 | 换成“[粉丝数已隐去]”“[点赞数已隐去]” |
| 截图里别人的名字和昵称，包括引用消息里显示的用户昵称 | 不写，用“队友”“用户”代替 |
| 截图里的聊天内容 | 照常用文字记录 |
| 其余内容 | 照常保存 |

以后遇到同类内容，按这张表处理后直接上传，不用再问。新的、拿不准的内容再问用户，例如别人的联系方式、未公开的合同或报价、别人的完整聊天记录。

## 附件

- 用户发的截图和 PDF 拿不到原文件，聊天记录里写文字描述或摘要。
- 描述截图时不写聊天列表里其他联系人的名字，也不写截图角落里和内容无关的网址和账号。
- PDF 摘要不写作者署名。

## 提交前检查

写完后用 grep 搜一遍新文件，确认隐去的内容没有漏掉，例如名次、粉丝数和截图里出现过的名字。搜索用的关键词本身也是要隐去的内容，不要写进仓库。

## 让最后一轮回复也存全文

以前的问题：最后一条回复是在提交之后才发出的，记录里只能先写要点（见 2026-11-04 聊天记录的第 13、14 轮）。

做法：

1. 写好聊天记录、经验和 README，提交并推送到 `sync/...` 分支，开 PR，拿到 PR 编号和链接。
2. 把最后一轮要发给用户的回复全文（带上 PR 链接）写进聊天记录，再提交、推送到同一个分支。
3. 合并 PR，确认 `main` 上有这些文件。
4. 把第 2 步写进去的那段回复原样发给用户。
