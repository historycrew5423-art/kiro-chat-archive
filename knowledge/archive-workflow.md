# 归档同步：隐私处理和最后一轮回复

来自 2026-11-05 的会话。规则本身见 `.kiro/steering/archive-sync.md`，这里记具体怎么做、用户确认过什么。

## 用户确认过的隐私处理

2026-11-05 的聊天里有用户的个人经历（比赛名次、账号粉丝数）和一张与队友的微信聊天截图。Kiro 先问了用户，用户同意按下面的办法处理后上传：

| 内容 | 处理 |
| --- | --- |
| 比赛名次 | 换成“[名次已隐去]”，比赛名称保留 |
| 视频号粉丝数、小红书点赞数 | 换成“[粉丝数已隐去]”“[点赞数已隐去]” |
| 截图里别人的名字和昵称，包括引用消息里显示的用户昵称 | 不写，用“队友”“用户”代替 |
| 截图里的聊天内容 | 照常用文字记录 |
| 其余内容 | 照常保存 |

以后遇到同类内容，按这张表处理后直接上传，不用再问。新的、拿不准的内容再问用户，例如别人的联系方式、未公开的合同或报价、别人的完整聊天记录。

## 附件

- 用户发的截图和 PDF 拿不到原文件，聊天记录里写文字描述或摘要。
- 描述截图时不写聊天列表里其他联系人的名字，也不写截图角落里和内容无关的网址和账号。
- PDF 摘要不写作者署名。

## 提交前检查

写完后用 grep 搜一遍新文件，确认隐去的内容没有漏掉，例如名次、粉丝数和截图里出现过的名字。搜索用的关键词本身也是要隐去的内容，不要写进仓库。

## 让最后一轮回复也存全文

以前的问题：最后一条回复是在提交之后才发出的，记录里只能先写要点（见 2026-11-04 聊天记录的第 13、14 轮）。

做法：

1. 写好聊天记录、经验和 README，提交并推送到 `sync/...` 分支，开 PR，拿到 PR 编号和链接。
2. 把最后一轮要发给用户的回复全文（带上 PR 链接）写进聊天记录，再提交、推送到同一个分支。
3. 等几秒再合并 PR，合并时带上 `-f sha=$(git rev-parse HEAD)`。推送后马上合并会返回 HTTP 405（见 `kiro-sandbox-notes.md`）。合并后确认 `main` 上有这些文件。
4. PR 合并以后还要补东西（比如新发现的坑），另开分支和 PR，不要往已合并的分支上推。
5. 把第 2 步写进去的那段回复原样发给用户。写进记录以后就不要再改措辞：2026-11-05 第 14 轮就是发出前又改了措辞，记录和实际发出的对不上，第 15 轮才改正；第 18 轮又犯了一次（15 处措辞不同），第 20 轮改正。回复只写一遍：写进记录的就是定稿，发出的消息逐字照抄，不再润色。

## 怎么分轮

用户的一条消息里有空行分段，仍然只算一轮。2026-11-05 曾把一条分了两段的消息错记成第 15、16 两轮，第 16 轮改正。

## 开新分支要单独一步

2026-11-05 第 18 轮：把 `git checkout -b 新分支` 和改文件的工具调用放在同一批里发出。改文件先执行完，checkout 因为“本地有改动会被覆盖”而失败，后面的提交落到了已经合并的旧分支上，推送也失败了。

做法：先单独执行 `git fetch origin main && git checkout -b sync/... origin/main`，确认 `git branch --show-current` 是新分支，下一步再改文件。

## 别的会话可能同时在写这个仓库

同一天可能有好几个 Kiro 会话在同步（2026-11-05 第 18 轮时，另一个会话刚合并了 PR #10）。所以：

- 每次都从最新的 `origin/main` 开分支，不要从自己上一个分支接着开。
- README 的会话索引最容易冲突。解决冲突时两边的行都留下，不要覆盖别的会话写的内容。
- 别的会话写的文件（它的聊天记录、它新加的经验）不要改。

## 把归档里的项目交给别人改

2026-11-05 第 18 轮：用户要把游戏交给队友改。

- 先验证别人拿到能不能用：只下载这个文件夹（`git clone --filter=blob:none --sparse` + `git sparse-checkout set <目录>`），`npm ci && npm run build`，比对打包结果和仓库里的是否一致（`sha256sum`）。
- 在项目 README 里写一节交接说明：只下载文件夹的命令、改完要重新打包并提交打包结果、常改的东西在哪个文件、换素材要注意什么。
- 建议用户另开一个仓库给别人改：归档仓库有聊天记录，Kiro 也会往里同步，多人在这里改容易冲突。Kiro 建不了仓库（403），要用户手动建，再由 Kiro 推进去。
- 新仓库如果设成私有，htmlpreview 的“直接打开”链接就不能用了（它读不到私有仓库），只能本地运行。

## 会话跨天时的日期

用户在北京时间，沙盒里 `date` 显示的是 UTC。日期按北京时间算：`TZ=Asia/Shanghai date +%F`。

同一个会话跨天时，聊天记录还写在原来那个文件里；新的一轮在标题上标日期，分支名和提交信息用当天的日期。2026-11-06 发现第 19 轮其实是 11-06 发的，提交信息却写成了 11-05，第 20 轮补标了日期。
