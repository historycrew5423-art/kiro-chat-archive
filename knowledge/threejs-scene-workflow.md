# 用代码做 Three.js 场景：工作流和踩过的坑

来自 2026-11-04 的两个场景：雨夜城市（`files/2026-11-04-rainy-city/`）和峡谷拱门（`files/2026-11-04-canyon-arch/`）。
以后做类似的 3D 场景，先读这份。

## 工作流

1. **查当前版本和 API。** AI 容易写出旧版写法。先 `npm view three version`，锁定版本，看 release notes 和迁移指南。
   - 2026-11 时最新是 r187。r183 起 `PostProcessing` 改名 `RenderPipeline`，`Clock` 弃用改用 `Timer`；r186 删了 `PCFSoftShadowMap`。
2. **拆解参考图。** 把画面拆成几个部分（主体、地面、天气、氛围），每部分对应一种具体技术，再开始写代码。只说“要好看”没用。
3. **定方案和验证方式。** 先想好怎么截图验证，再选渲染器。
4. **按效果拆模块写，打包成一个文件。** esbuild 打包成 IIFE 格式的 `app.js`，`<script src>` 普通引入。打包后的文件也提交，静态托管可以直接用。
   新场景可以直接从上一个场景复制：`glsl.js`（噪声）、`serve.mjs`、`post.js` 里的安全阀、主程序里的画质档位 / 截图开关 / 自适应分辨率。
5. **加调试截图开关。** 例如 `__scene.shot({ t, yaw, pitch })`：用固定时间和视角渲染一帧后停住。软件渲染很慢，没有这个开关就截不了图，也没法前后对比。
6. **截图迭代，每轮只解决几个明显问题。** 每轮至少看：正面、转一个角度、特殊状态（比如闪电）、手机竖屏。同时检查控制台有没有报错。
   峡谷场景迭代了 7 轮，每轮都是“看图 → 列出最明显的 3~5 个问题 → 改参数或改做法”。
7. **尽早让用户在真机上看。** 软件渲染和真显卡的计算行为不同（见下面的 NaN 问题）。第一版出来就给可以直接打开的链接。
8. **用户反馈的 bug：先复现原理，再修，再验证。** 例如故意放一个坏像素，复现整屏变黑。

## 场景技术清单

### 雨夜城市

| 效果 | 做法 |
| --- | --- |
| 大量建筑 | 单位立方体 `InstancedMesh`，一次绘制。窗户在片元着色器里按楼的实际尺寸算（`instanceMatrix` 每列的长度就是尺寸）。远处窗格小于一两个像素时换成块平均亮度，避免摩尔纹 |
| 杆件结构（塔、塔吊、栏杆） | 用“两端点 + 粗细”描述每根杆，合成一个实例网格 |
| 湿地面 | `Reflector` 渲染镜像图，按噪声分积水和湿水泥：积水清晰反射，湿水泥用 mip 偏移模糊并沿竖直方向多次采样拉长；叠加涟漪法线和菲涅尔 |
| 雨 | `LineSegments`，下落和循环在顶点着色器里算；亮度按到灯的距离算。倒影相机关掉雨的图层 |
| 蒸汽 / 烟雾 | 朝向镜头的实例面片，采样预先生成的可平铺噪声图（比每像素算 fbm 便宜） |
| 后期 | 坏像素清零 → 泛光 → 线性空间调色 → `OutputPass`（色调映射）→ 显示空间的颗粒和暗角 |
| 声音 | Web Audio 滤波噪声合成，必须由用户点击触发 |
| 画质 | 按设备分档；运行几秒后如果平均帧率低于阈值，自动降低像素比 |

### 峡谷拱门

| 效果 | 做法 |
| --- | --- |
| 地形 / 岩体 | 先按简单形状生成网格（拱门正面的环形网格、洞口内壁、左右岩壁、台阶），再统一加一个三维噪声位移场 D(p)。位移只取决于位置，不同网格的共享边会被推到同一处，不会裂开 |
| 拱门形状 | 洞口轮廓 = 两条竖边 + 半椭圆，按弧长参数化；正面网格沿轮廓法线向外延伸，内壁沿深度方向延伸 |
| 岩石质感 | 在 `MeshStandardMaterial.onBeforeCompile` 里注入：三向投影噪声算颜色、苔藓（按法线朝上的程度）、水渍、竖向节理；用 `dFdx/dFdy` 做凹凸（Mikkelsen 公式）。保留 three 的光照和阴影 |
| 全场景雾 | 直接替换 `THREE.ShaderChunk.fog_*` 四个代码块：高度雾解析积分 + 朝太阳方向的暖色散射。世界坐标用 `cameraPosition + transpose(mat3(viewMatrix)) * mvPosition.xyz` 算，任何内置材质都适用 |
| 逆光的近似 | “从这个点朝太阳看，视线是否穿过洞口”：把射线投到拱门平面上，用洞口的有向距离判断。用于树叶透光、瀑布发光、水面闪光这些不走阴影贴图的效果 |
| 光束 | 后期：亮度阈值取出太阳附近的亮部 → 从太阳屏幕位置做 64 次采样的径向模糊 → 叠加回去 |
| 植被 | 在岩壁网格顶点上按“朝上程度、高度、噪声斑块”算概率撒点，每处 1~3 团挤在一起；叶团是噪声变形的二十面体实例；近景用画在 canvas 上的叶簇贴图做面片 |
| 湖面 | `Reflector` + 几组正弦波 + 噪声细纹做法线，菲涅尔混合；太阳高光用噪声打散成碎光 |
| 便宜的水潭 | 不做真实倒影：把反射方向投到拱门平面，落在洞口里给天空色，否则给岩壁色 |
| 瀑布 | 沿抛物线（水平位移 ∝ √下落距离）弯下去的条带；片元里用 x 方向高频、y 方向低频并随时间下移的噪声画水丝和水沫；出水口用射线打到岩壁上找 |
| 远方城市 | 分段收窄的塔楼 + `ExtrudeGeometry` 做的拱券模块排成高架桥，靠雾变成剪影 |

## 踩过的坑

### 窗户里出现杂色噪点
- 现象：部分窗户里是彩色的电视雪花点。
- 原因：每个实例都相同的参数（随机种子）通过普通 varying 传到片元着色器，插值后有极小的误差；哈希函数把误差放大，按像素得到不同的随机结果。
- 修复：用 `flat varying` 传实例常量，种子再量化一次（`floor(x * 997.0 + 0.5) / 997.0`）。

### 真显卡上画面闪烁、大块变黑（软件渲染看不出来）
- 现象：Mac Chrome 上只有画面顶部一条正常，其余是黑的，并且一闪一闪。
- 原因：某些像素算出 NaN。泛光会做多级大范围模糊，一个 NaN 像素会扩散成整块黑色。
- 来源：开 MSAA 时，像素中心可能落在三角形外，插值出的值会超出顶点值的范围（比如略小于 0）；`pow(负数, y)` 在真显卡上是 NaN。
- 修复：
  1. 所有 `pow` 的底数先 `clamp` 到合法范围。
  2. 在泛光之前加一个清理 pass：`(floatBitsToUint(x) & 0x7f800000u) == 0x7f800000u` 判断 NaN / 无穷大并清零，再限制最大亮度。用位运算是为了防止编译器的快速数学优化把 `isnan` 判断去掉。
- 验证方法：临时放一个输出 `uZero / uZero` 的小方块（用 uniform 防止编译期常量折叠），对比有无清理 pass。
- **以后每个新场景都默认带上这个清理 pass。**

### 构图像一堵墙
- 现象：近处的楼太高、太近，看不到天空，窗户显得很大。
- 修复：近处一排楼往后推；高度上限随距离增加（`h = min(h, 40 + 距离 * 0.34)`）；超高的楼只放在远处；加大指数雾，让远处的楼融进天空。

### 逆光场景整个画面发白
- 现象：镜头朝着太阳，雾、光束、泛光叠在一起，画面像蒙了一层牛奶。
- 原因：雾的“朝太阳发光”项指数太低（`pow(s, 5)`），镜头前方大半个画面都在太阳附近，全部被提亮；雾密度也太大。
- 修复：雾密度从 0.0019 降到 0.0008；散射项改成 `pow(s, 12)` + 很窄的 `pow(s, 80)`；光束阈值提高到 4.5、强度降到 0.28；泛光阈值 2.2。

### 植被像漂浮的绿色生菜
- 原因：叶团太大、太亮、太圆；逆光透光项对所有叶团都生效；撒点时沿法线推得太远，看起来离开了岩壁。
- 修复：叶团缩小并成簇摆放；颜色调暗；透光乘上边缘系数（只在轮廓附近明显）；沿法线只推 0.12 倍半径；陡壁上的零星叶团大幅减少。

### 位移函数有跳变 → 表面出现锯齿状台阶
- 现象：被照亮的岩面上出现一排排锯齿。
- 原因：为了做岩层台阶，用了 `smoothstep(..., fract(y / 17))`，在 `fract` 回绕处值从 1 跳回 0。网格按 3~4 米采样，跳变处就成了锯齿。
- 修复：周期函数必须首尾连续，例如 `smooth(0.55, 0.85, f) * (1 - smooth(0.85, 1.0, f))`。

### 岩石颜色出现木纹 / 等高线
- 原因：岩层条纹 `sin(y * k + 噪声 * 14)` 的噪声扰动太强，条纹被扭成一圈圈等高线；再用阈值很陡的噪声做裂缝，凹凸后像迷宫。
- 修复：扰动降到 `噪声 * 4`，条纹对比度降低；去掉陡阈值裂缝，改成低频、竖向拉长的节理噪声。

### 太阳放进画面后，水面中间一大团白光
- 原因：水面高光有一个很宽的 `pow(rs, 60)` 项，倒影里的太阳圆盘亮度也太高（90），再经过泛光和光束。
- 修复：去掉宽高光，窄高光乘噪声变成闪烁的碎光；太阳圆盘亮度降到 28。

### 雾气粒子像一个个白球，和水面相交有硬边
- 修复：密度用 `mask * mask` 让边缘更软；片面底部渐隐；粒子中心抬高到半径以上；整体透明度降到 0.26。

### 灯光方向和画面里的太阳可以分开
- 太阳圆盘要放在拱门洞口里，但这样光线几乎平行于左侧岩壁，左壁一直是暗的。
- 做法：天空、雾、透光用画面里的太阳方向 `SUN_DIR`；真正投影的 `DirectionalLight` 用更偏右、更高的 `LIGHT_DIR`。画面更好看，观众看不出不一致。

### 其他
- 无头浏览器里没有中文字体，界面上的中文会显示成方框。截图前隐藏界面文字，不代表真机有问题。
- `ShaderMaterial` 要支持雾：`fog: true`，uniforms 里合并 `UniformsLib.fog`，着色器里 include `fog_pars_*` 和 `fog_*`，顶点着色器里的变量必须叫 `mvPosition`。如果替换了雾代码块（峡谷场景），自定义着色器就直接调用同一份 GLSL 函数，不要再 include。
- 多个材质共用同一个 uniform 对象，改一处全场景生效。`Reflector` 会克隆传入的 uniforms，创建后要把需要共享的 uniform 重新赋值回去。
- 倒影相机是在第一次调用 `getReflectionCamera(camera)` 时从主相机克隆的，图层要在那之后再单独设置。
- 用 `onBeforeCompile` 生成多种变体时，必须给每种变体写不同的 `customProgramCacheKey()`。否则 three 按函数源码缓存着色器，不同参数会共用同一个编译结果。
- 叠加混合的发光物（灯笼、光点）不能直接套雾色，否则雾色会被叠加成一层光；只乘大气透过率 `exp(-光学深度)`。
