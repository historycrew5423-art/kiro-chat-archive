# 别人用 Opus 5.5 搭的 3D 项目：怎么做的、做到什么程度

来自 2026-11-05 第 21 轮的调研。以后用户问“能做到多好”“别人怎么做”，或者要定一个大场景的做法，先看这份。
截图是各项目作者的作品，没有存进仓库，只留链接。

## 看过的项目

## 结论

1. **好看的几乎都选了画风**（动漫、低多边形、毛毡、线稿）。画风把“代码几何体不够真实”藏住了。走写实路线的项目近看和我们的问题一样：树是团、楼是盒子。照片级写实是共同的天花板。
2. **画面密度是代码量和时间堆出来的。** 好看的项目代码量是绿环之城的 10 到 20 多倍，花了几天到几百小时。
3. **都有真显卡和看图的工具链**：参考图对比、前后对比、联系表、盲测。Middle-earth 作者的意思是：AI 写出的几何体可以能跑但很难看，没有审查的生成只是更快地乱试。
4. **先搭共用系统再填内容**，内容才能一直往上加而不乱；子代理并行做各自的模块，主代理审查合并。
5. **展示图不一定是实时画面**：Middle-earth 的 README 图和电影是离线多次采样渲染的。拿别人的截图比较时要分清。

## 以后做大场景的建议

- 先和用户定画风：写实还是风格化。参考图是照片级写实的，要提前说清网页实时渲染只能“某个角度接近”。
- 多会话做：第一个会话只搭架构（共用系统 + 数据格式 + 截图审查工具），之后每个会话填一块内容。
- 每轮请用户在真机上看，或者想办法拿到有显卡的验证环境；沙盒软件渲染验证不了 WebGPU 效果。
